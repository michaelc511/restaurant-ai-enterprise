Beyond the PDF: Live Restaurant Data Through a FastMCP Server and Google Sheets

Category 8: Tools & Data Grounding (#mcp, #tools). Feature covered: F8 (FastMCP Server Integration).

A PDF menu is a snapshot. Today's specials, a holiday closure, or a private event next Saturday change daily and will never be in it. F8 connects the assistant to a live source — a Google Sheet the staff can edit — and exposes that data two ways: as plain functions the API calls directly, and as standard Model Context Protocol (MCP) tools any AI agent can use.

The Data Source: One Google Sheet (core/sheets.py)

  • Access: gspread authenticates with a Google service account (the key file lives in secrets/, which isn't committed). The spreadsheet must be shared with that account.
  • Two tabs: specials (Day, Dish Name, Category, Description, Price, Allergens, Is Active) and dates (Date, Day, Event / Holiday, Status, Open Time, Close Time, Staff Notes).
  • get_daily_specials(day) returns active specials, optionally filtered to a weekday such as "Fri." Rows marked "All Week" are included for every day.
  • get_hours_and_events(target_date) returns hours, holiday, or closure rows for a specific date, or all rows.
  • Always fresh: only the authenticated client is cached; sheet data is re-read on every call, so a staff edit shows up on the next question.
  • Clear errors: a missing sheet, a renamed tab, a network problem, or a rate limit is turned into a RuntimeError with a readable message.

Consumer 1: The MCP Server (api/mcp_server.py)

MCP is an open standard that lets AI applications discover and call external tools in a uniform way. With FastMCP, exposing the sheet takes a few lines:

mcp = FastMCP("restaurant-ops-mcp")

@mcp.tool
def daily_specials(day: Optional[str] = None) -> list[dict]:
    """Look up today's (or a given weekday's) active daily specials for the sushi menu."""
    return get_daily_specials(day)

@mcp.tool
def hours_and_events(target_date: Optional[str] = None) -> list[dict]:
    """Look up restaurant hours, holiday schedules, or closure notices."""
    return get_hours_and_events(target_date)

if __name__ == "__main__":
    mcp.run(transport="stdio")
  • Docstrings become tool descriptions. An agent reads them to decide when to call each tool and what arguments to pass.
  • stdio transport: an MCP client such as Claude Desktop launches the server as a subprocess and talks to it over standard input and output.
  • Stateless: no data or per-session state is kept between tool calls.
  • Verified separately: test_mcp_connection.py starts the server over stdio and calls both tools.

Consumer 2: The Restaurant API

The same functions are called directly by the API — one implementation, two consumers.

  • GET /specials and GET /hours return the sheet's rows as JSON.
  • Routing inside /ask: detect_ops_intent() is a simple keyword check. A question containing "special" goes straight to the sheet. A question containing "hour," "open," "close," or "holiday" is treated as an hours question.
  • Understanding "tomorrow": resolve_target_days() turns phrases like "tomorrow," "in 3 days," "Friday," or "this weekend" (Saturday and Sunday) into real dates.

Specials vs. hours: two different paths

  • Specials only ever exist in the sheet, so the answer comes straight from it — no retrieval, no LLM call.
  • Hours are different: the regular weekly schedule is in the PDF menu. So the RAG chain answers first, with the resolved date added to the question ("The date being asked about is Friday, …"). Then any matching holiday or event rows from the sheet are appended.
  • Hours questions skip conversation memory. Earlier turns about dishes were pulling retrieval away from the hours section of the menu, and an hours lookup is a standalone factual question anyway.

User: "What are today's specials?"

Answer: "Specials:
[Fri] <dish name> (<price>) - <description> …"

(Read live from the specials tab; top_match says "(F8) Live data from Google Sheets, not a PDF chunk." The actual dishes depend on what the staff have entered in the sheet.)

User: "What are your hours on Friday?"

Answer: "Friday hours are 12:00 PM to 11:00 PM." — followed by any Friday event or holiday rows from the sheet.

Limitations

  • One sheet for every cuisine. There's a single spreadsheet, named "sushi," so a specials question on the steak or italian menu currently returns the sushi sheet's specials.
  • Keyword routing is blunt. Any question with "special" in it goes to the sheet. A newer intent classifier rejects off-topic questions first, but the specials/hours routing is still keyword-based.

What's next (not yet built): a sheet per restaurant, and letting an agent engine call the MCP tools itself instead of relying on keyword routing. Neither is implemented in this project yet.
